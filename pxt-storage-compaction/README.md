# Actual write-driven RAFFS compaction

Read the [contract](../docs/PXT-STORAGE-COMPACTION.md) before qualification.
The existing object-remount caller remains unchanged. This producer calls its
unchanged link-only producer, then replaces only the authored probe and settings
accessor object. The parent guest is never executed or relabelled as the new
case. Original RAFFS/settings algorithms and the configured spacing policy stay
intact. The original source packages, actual libraries/members and notices are
retained with both link packets.

Two fresh authored modes share one source-bound image. The observer selects mode
only after actual startup and before entering the caller; it supplies no storage
contents or successful returns. Positive writes versioned4096-byte values until
actual bank movement, then checks retained/deleted/internal values, exact lists
and a fresh wrapper remount. The spacing case keeps one wrapper and continues
the write burst to the original fourth-compaction panic921. It records actual
clock returns whose LR is inside `tryGC`, computes the unchanged horizon and
checks both banks against the snapshot before the triggering write.

The positive caller has14710 checks in five stages, retains the original60-check
GC/service caller and holds managed/native data across real collection. The
observer records real method entry/returns, generations1→2→3 and code/data/neighbor
canaries. The new80M bound belongs only to this case. Two compiled actual-source
mutants must expose a missing committed bank header after successful write or
256 specifically shifted kept bytes, rather than an unrelated panic or timeout.

Only hosted CI builds/runs the engine and ARM caller. Compiled dependency caches
may survive a failing case; every selected guest and mutation still executes.
Independent original readers are frozen before execution; original failures are
retained. This is no reset, power-loss, physical-endurance, full-board, generated
Arcade, performance or project-wide licence-clearance result.
